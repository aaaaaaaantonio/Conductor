# Conductor

Веб-панель для запуска автотестов. Java- и Python-тесты отправляются сборкой в Jenkins; Python можно запустить и локально (VM-режим) с живым логом и кнопкой «Остановить». Есть тестирование агентов (свои скрипты с настраиваемыми параметрами), справочники команд/стендов/тестов/датасетов и история запусков.

Стек: FastAPI, SQLModel (SQLite), Jinja2 + htmx, SSE для живых логов.

## Быстрый старт

Нужны Python 3.12+ и [uv](https://docs.astral.sh/uv/).

```bash
uv sync
uv run uvicorn app.main:app
```

Откройте http://127.0.0.1:8000 — откроется вкладка Python. Для разработки добавьте `--reload`.

Перед первым запуском заполните справочники (вкладка «Справочники»): команды, стенды, имена тестов, датасеты — из них строятся формы запуска.

Чтобы запускать сборки в Jenkins, каждый пользователь вводит свои токены на странице «Доступы». Они хранятся в зашифрованной HttpOnly-cookie, ключ шифрования — `CONDUCTOR_SECRET_KEY`. **Задайте его вне разработки:** без него ключ генерируется заново при каждом старте и все токены пропадают.

## Переменные окружения

Все настройки читаются в `app/config.py`. Относительные пути в переменных считаются от текущей директории, значения по умолчанию — от корня проекта.

### База данных и логи

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `DATABASE_URL` | `sqlite:///<проект>/test_runner.db` | URL базы (SQLAlchemy). |
| `JOB_LOG_DIR` | `<проект>/job_logs` | Куда пишутся логи локальных запусков. |
| `JOB_RETENTION_DAYS` | `5` | Завершённые запуски и их логи старше этого числа дней удаляются. |

### Jenkins

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `JENKINS_BASE_URL` | `http://localhost:8080` | Адрес Jenkins. |
| `JENKINS_JOB_NAME_JAVA` | `java-tests` | Jenkins-джоба для Java-запусков и их перезапусков. |
| `JENKINS_JOB_NAME_PYTHON` | `python-tests` | Jenkins-джоба для Python-запусков в режиме Jenkins. |

### Python VM-режим

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PYTHON_TEST_RUNNER_PATH` | `./run-python-tests.sh` | Скрипт, который запускается локально (путь от текущей директории). |

### Allure

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `ALLURE_BASE_URL` | пусто | Адрес Allure TestOps; по нему проверяется токен Allure на странице «Доступы». Пусто — проверка пропускается. |

### Токены пользователей (cookie)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `CONDUCTOR_SECRET_KEY` | пусто (случайный ключ на процесс) | Ключ шифрования cookie с токенами. Любая строка; смена ключа разлогинивает всех. |
| `COOKIE_SECURE` | `false` | `true`, когда Conductor работает по HTTPS. |
| `CREDS_SESSION_IDLE_TTL` | `43200` (12 ч) | Сколько секунд без активности живут токены без галочки «Запомнить на этом компьютере». |
| `CREDS_REMEMBER_IDLE_TTL` | `2592000` (30 дн.) | То же с галочкой «Запомнить». |
| `CREDS_REFRESH_AFTER` | `60` | Как часто (в секундах) cookie переиздаётся для продления. |
| `CREDS_MAX_LIFETIME` | `315360000` (10 лет) | Жёсткий предел с момента ввода токенов, как бы активно ни работал пользователь. |

## Jenkins-хуки

Вся отправка в Jenkins — в `app/execution/jenkins_launch.py`. Сюда дописывается своя логика; остальной код вызывает эти функции и показывает результат.

| Функция | Когда вызывается |
|---|---|
| `launch_in_jenkins(source, job_name, params, creds)` | «Запустить» на вкладке Java или на вкладке Python в режиме Jenkins. `source` — `"java"` или `"python"`, `params` — непустые значения формы. |
| `restart_java(build_number, creds)` | «Перезапустить» на вкладке Java; `build_number` — номер сборки (≥ 1). |
| `restart_python(build_number, creds)` | «Перезапустить» на вкладке Python. |

Контракт у всех трёх одинаковый:

- вызываются синхронно, пока пользователь ждёт ответа;
- вернуть `LaunchResult(message, url=None)` — `message` покажется в панели лога текстом, `url` (если есть) — ссылкой;
- бросить исключение — вместо сообщения покажется текст ошибки;
- `creds` — личные токены пользователя со страницы «Доступы»; без них хук не вызывается. Для HTTP-авторизации в Jenkins есть `creds.jenkins_auth()`.

Сейчас хуки просто ставят сборку через `trigger_build` (`app/execution/jenkins_client.py`). Статус и логи Jenkins-сборок Conductor не отслеживает — это сознательное решение.

## Python VM-режим

В режиме VM на вкладке Python Conductor сам запускает `PYTHON_TEST_RUNNER_PATH` и передаёт значения формы флагами `--имя=значение`:

| Флаг | Значение | Обязательный |
|---|---|---|
| `--team` | id команды из справочника | да |
| `--stand` | id стенда | да |
| `--regression-type` | тип регрессии | да |
| `--test-name` | «команда запуска» теста из справочника, если задана, иначе id теста | нет |
| `--dataset` | id датасета | нет |

Необязательные флаги без значения не передаются. Тестирование агентов работает так же: запускается путь, указанный в тесте, параметры передаются как `--флаг=значение`, чекбоксы и фиксированные флаги без значения — просто `--флаг`.

stdout и stderr скрипта пишутся в `JOB_LOG_DIR/job-<id>.log` и сразу транслируются в браузер. Код выхода 0 — «Успешно», иначе «Ошибка». Скрипт запускается в своей группе процессов: «Остановить» завершает всю группу, включая дочерние процессы shell-обёрток. Запуски, которые висели при остановке сервера, при следующем старте помечаются как «Ошибка».

## Данные

- База — SQLite в `test_runner.db` (или `DATABASE_URL`), таблицы создаются при старте.
- Логи локальных запусков — в `job_logs/` (или `JOB_LOG_DIR`).
- При старте и затем раз в час удаляются завершённые запуски старше `JOB_RETENTION_DAYS` вместе с логами, а также «осиротевшие» файлы логов того же возраста. Активные запуски не удаляются.

## Тесты

```bash
uv run pytest
```

Тесты используют базу в памяти и временную папку для логов — рабочие `test_runner.db` и `job_logs/` они не трогают.
