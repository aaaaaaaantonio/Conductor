# TestDepot

Веб-панель для запуска автотестов. Java- и Python-тесты отправляются сборкой в Jenkins; Python можно запустить и локально (VM-режим) с живым логом и кнопкой «Остановить». Есть тестирование агентов (свои скрипты с настраиваемыми параметрами), справочники команд/стендов/тестов/датасетов и история запусков.

Стек: FastAPI, SQLModel (SQLite), Jinja2 + htmx, SSE для живых логов.

## Быстрый старт

Нужны Python 3.12+ и [uv](https://docs.astral.sh/uv/).

```bash
uv sync
uv run uvicorn app.main:app --timeout-graceful-shutdown 5
```

`--timeout-graceful-shutdown 5` нужен для остановки: каждая открытая вкладка TestDepot держит поток live-обновлений, и без таймаута uvicorn ждёт их закрытия бесконечно.

Запускайте ровно **один** worker uvicorn (без `--workers N`): запущенные на VM процессы, кнопка «Остановить» и живой лог держатся в памяти процесса, а при старте каждый worker помечал бы чужие активные запуски как упавшие.

Откройте http://127.0.0.1:8000 — откроется вкладка Python. Для разработки добавьте `--reload`.

Чтобы попробовать VM-режим без настоящих тестов, возьмите заглушку — она печатает переданные флаги и через 5 секунд завершается успешно:

```bash
cp run-python-tests.example.sh run-python-tests.sh
```

### Запуск в фоне (nohup)

```bash
cp .env.example .env   # один раз: впишите TESTDEPOT_SECRET_KEY и нужные переменные
nohup uv run --env-file .env uvicorn app.main:app --host 0.0.0.0 --port 8000 --timeout-graceful-shutdown 5 > testdepot.out 2>&1 &
echo $! > testdepot.pid
```

Сервер переживёт закрытие терминала. Лог — в `testdepot.log` (`LOG_FILE` в `.env.example`): при каждом запуске он начинается заново, а при росте до `LOG_MAX_MB` уходит в `testdepot.log.1`, `.2` — на диске не больше `LOG_MAX_MB × (LOG_BACKUPS + 1)`, по умолчанию 30 МБ. В `testdepot.out` попадает только то, что случилось до старта приложения, например ошибка в `.env`. Смотреть лог: `tail -f testdepot.log`. Остановить:

```bash
kill "$(cat testdepot.pid)" && rm testdepot.pid
```

Запуски на VM, которые шли в момент остановки, останавливаются вместе с сервером и помечаются как «Ошибка».

## Переменные окружения

Все настройки читаются в `app/config.py`. Числовые переменные должны быть целыми ≥ 1 (`CREDS_REFRESH_AFTER` — ≥ 0), иначе TestDepot не стартует и пишет, какая переменная неверна. Относительные пути в переменных считаются от текущей директории, значения по умолчанию — от корня проекта.

### База данных и логи

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `DATABASE_URL` | `sqlite:///<проект>/test_runner.db` | URL базы (SQLAlchemy). |
| `JOB_LOG_DIR` | `<проект>/job_logs` | Куда пишутся логи локальных запусков. |
| `JOB_RETENTION_DAYS` | `5` | Завершённые запуски и их логи старше этого числа дней удаляются. |
| `LOG_TAIL_LINES` | `200` | Сколько последних строк лога показывает панель; полный лог — по ссылке «Скачать полный лог». |
| `LOG_LEVEL` | `INFO` | Уровень лога самого приложения (`DEBUG`, `INFO`, `WARNING`, `ERROR`): почему запрос отклонён (4xx и причина), запуски и их итог. Пишется в тот же вывод, что и лог uvicorn. |
| `LOG_FILE` | пусто (лог в консоль) | Файл для лога приложения и uvicorn вместо консоли. Очищается вместе с частями `.1`, `.2`… при каждом запуске. |
| `LOG_MAX_MB` | `10` | Размер `LOG_FILE`, при котором он уходит в `.1`, а запись начинается в новый файл. |
| `LOG_BACKUPS` | `2` | Сколько прошлых частей хранить (`.1` — самая свежая); `0` — только текущий файл. |
| `LOG_LINE_MAX_CHARS` | `5000` | Строка длиннее показывается в браузере последними этим числом символов; в файле лога она хранится целиком. |

### Jenkins

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `JENKINS_BASE_URL` | `http://localhost:8080` | Адрес Jenkins. |
| `JENKINS_JOB_NAME_JAVA` | `java-tests` | Jenkins-джоба для Java-запусков и их перезапусков. |
| `JENKINS_JOB_NAME_PYTHON` | `python-tests` | Jenkins-джоба для Python-запусков в режиме Jenkins. |

### Python VM-режим

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PYTHON_TEST_RUNNER_PATH` | `./run-python-tests.sh` | Скрипт, который запускается локально (путь от текущей директории). |

### Allure

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `ALLURE_BASE_URL` | пусто | Адрес Allure TestOps; по нему проверяется токен Allure на странице «Доступы». Пусто — проверка пропускается. |

### Jira Zephyr

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `JIRA_BASE_URL` | пусто | Адрес Jira Server/DC, например `https://jira.company.ru`. Токен Zephyr — это Personal Access Token Jira; он проверяется запросом `GET /rest/api/2/myself`. Пусто — проверка пропускается. |

### Токены пользователей (cookie)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `TESTDEPOT_SECRET_KEY` | пусто (случайный ключ на процесс) | Ключ шифрования cookie с токенами. Любая строка; смена ключа разлогинивает всех. |
| `COOKIE_SECURE` | `false` | `true`, когда TestDepot работает по HTTPS. |
| `TESTDEPOT_ALLOWED_ORIGINS` | пусто | Защита от CSRF: POST/PUT/DELETE с заголовком `Origin` чужого сайта отклоняются (403). По умолчанию `Origin` сверяется с `Host` запроса; если reverse proxy меняет `Host`, перечислите здесь адреса TestDepot через запятую, например `https://testdepot.company.ru`. |
| `CREDS_SESSION_IDLE_TTL` | `43200` (12 ч) | Сколько секунд без активности живут токены без галочки «Запомнить на этом компьютере». |
| `CREDS_REMEMBER_IDLE_TTL` | `2592000` (30 дн.) | То же с галочкой «Запомнить». |
| `CREDS_REFRESH_AFTER` | `60` | Как часто (в секундах) cookie переиздаётся для продления. |
| `CREDS_MAX_LIFETIME` | `315360000` (10 лет) | Жёсткий предел с момента ввода токенов, как бы активно ни работал пользователь. |

## Jenkins-хуки

Вся отправка в Jenkins — в `app/execution/jenkins_launch.py`. Сюда дописывается своя логика; остальной код вызывает эти функции и показывает результат.

| Функция | Когда вызывается |
|---|---|
| `launch_in_jenkins(source, job_name, params, creds)` | «Запустить» на вкладке Java или на вкладке Python в режиме Jenkins. `source` — `"java"` или `"python"`, `params` — непустые значения формы. |
| `restart_java(build_number, creds)` | «Перезапустить» на вкладке Java; `build_number` — номер сборки (≥ 1). |
| `restart_python(build_number, creds)` | «Перезапустить» на вкладке Python. |

Контракт у всех трёх одинаковый:

- вызываются синхронно, пока пользователь ждёт ответа;
- вернуть `LaunchResult(message, url=None)` — `message` покажется в панели лога текстом, `url` (если есть) — ссылкой;
- бросить исключение — вместо сообщения покажется текст ошибки;
- `creds` — личные токены пользователя со страницы «Доступы»; без них хук не вызывается. Для HTTP-авторизации в Jenkins есть `creds.jenkins_auth()`.

Сейчас хуки просто ставят сборку через `trigger_build` (`app/execution/jenkins_client.py`). Статус и логи Jenkins-сборок TestDepot не отслеживает — это сознательное решение.

## Python VM-режим

В режиме VM на вкладке Python TestDepot сам запускает `PYTHON_TEST_RUNNER_PATH` и передаёт значения формы флагами `--имя=значение`:

| Флаг | Значение | Обязательный |
|---|---|---|
| `--team` | id команды из справочника | да |
| `--stand` | id стенда | да |
| `--regression-type` | тип регрессии | да |
| `--test-name` | «команда запуска» теста из справочника, если задана, иначе id теста | нет |
| `--dataset` | id датасета | нет |

Необязательные флаги без значения не передаются. Тестирование агентов работает так же: запускается путь, указанный в тесте, параметры передаются как `--флаг=значение`, чекбоксы и фиксированные флаги без значения — просто `--флаг`.

stdout и stderr скрипта пишутся в `JOB_LOG_DIR/job-<id>.log` и сразу транслируются в браузер. Код выхода 0 — «Успешно», иначе «Ошибка». Скрипт запускается в своей группе процессов: «Остановить» завершает всю группу, включая дочерние процессы shell-обёрток. Запуски, которые висели при остановке сервера, при следующем старте помечаются как «Ошибка».

## Возможности панели

- **Уведомления о завершении.** Когда VM-запуск, начатый из этого браузера, заканчивается, а вкладка TestDepot в фоне, на значке вкладки появляется красный кружок с числом, в заголовке — `(N)`, играет звук. По желанию — ещё и системное уведомление (клик открывает лог запуска). Настраивается кнопкой «Уведомления» внизу боковой панели: звук (или без звука), цифра на вкладке, системные уведомления, «только об ошибках». Настройки хранятся в браузере, у каждого свои. Системные уведомления браузер разрешает только по HTTPS или на `localhost` (например, через `ssh -L 8000:localhost:8000 <vm>`). Остановленные вручную запуски и Jenkins-сборки не уведомляют.
- **Длительность** VM-запусков видна в списке активных, в истории и в шапке лога; у идущих запусков она тикает.
- **Поиск по логу** — строка поиска над логом ищет по всему файлу, а не только по показанным строкам, с настоящими номерами строк; галочка «только ошибки» оставляет строки с `error`, `fail`, `fatal`, `Traceback`, `…Error`, `…Exception` и т. п. Фильтр применяется и к новым строкам идущего запуска.
- **Запоминание формы** — формы запуска Python, Java и тестов агентов помнят последние значения (в браузере).

## Данные

- База — SQLite в `test_runner.db` (или `DATABASE_URL`), таблицы создаются при старте.
- Логи локальных запусков — в `job_logs/` (или `JOB_LOG_DIR`).
- При старте и затем раз в час удаляются завершённые запуски старше `JOB_RETENTION_DAYS` вместе с логами, а также «осиротевшие» файлы логов того же возраста. Активные запуски не удаляются.

## Тесты

```bash
uv run pytest
```

Тесты используют базу в памяти и временную папку для логов — рабочие `test_runner.db` и `job_logs/` они не трогают.
